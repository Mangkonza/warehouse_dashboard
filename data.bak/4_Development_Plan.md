# แผนการพัฒนา (Development Plan) 
ตั้งแต่การจัดการไฟล์ไปจนถึง Dashboard

เพื่อสร้างระบบ Data Warehouse และ Dashboard จากไฟล์ Excel ชุดนี้อย่างเป็นระบบ ควรแบ่งการดำเนินงานเป็น 5 ระยะ (Phases) ดังนี้:

## Phase 1: การจัดการไฟล์ต้นทางและการนำเข้าข้อมูล (File Management & Data Ingestion)
1. **ออกแบบพื้นที่จัดเก็บ (Data Lake):** นำไฟล์ Excel ทั้งหมดไปจัดเก็บบน Cloud Storage (เช่น Google Cloud Storage, Amazon S3) หรือ Share Drive กลาง โดยจัดโครงสร้างโฟลเดอร์ให้เป็นระเบียบ เช่น `Raw_Data / ปีงบประมาณ / ประเภทรายงาน`
2. **Standardize Naming Convention:** กำหนดมาตรฐานการตั้งชื่อไฟล์ใหม่ เพื่อให้ Script ทำงานได้ง่าย (เช่น `Research_Project_2025.xlsx` แทนที่จะใช้ชื่อภาษาไทยยาวๆ)

## Phase 2: กระบวนการจัดการและปรับโครงสร้างข้อมูล (ETL - Extract, Transform, Load)
1. **Extract (สกัดข้อมูล):** ใช้ Python (Pandas) ทำการ Loop อ่านไฟล์ Excel ทั้งหมดในโฟลเดอร์
2. **Transform (แปลงข้อมูล):** 
   - **Data Cleansing:** ขจัดแถว Header ที่เป็น Merged cells (เช่น พวก `Unnamed: X`) ออก
   - **Unpivot Data:** แปลงข้อมูลที่มีการแยก Sheet เป็นเดือน (ม.ค. - ธ.ค.) ให้เป็น Long Format (เพิ่ม Column `Month` เข้ามา)
   - **Data Typing:** ปรับประเภทข้อมูลให้ถูกต้อง (เช่น แปลงข้อความตัวเลขที่มีเครื่องหมาย `,` ให้เป็น Float หรือ Integer)
   - **Master Data Mapping:** ตรวจสอบความถูกต้องของชื่อนักวิจัย คณะ หรือภาควิชา ให้ตรงกับตาราง Master
3. **Load (โหลดข้อมูล):** นำข้อมูลที่ผ่านการ Clean แล้ว โหลดเข้าสู่ฐานข้อมูลที่เป็น Data Warehouse (เช่น Google BigQuery, PostgreSQL, Snowflake)

## Phase 3: การสร้างแบบจำลองข้อมูล (Data Modeling)
1. **สร้าง Tables:** นำแนวคิด Star Schema หรือ Snowflake Schema ที่ออกแบบไว้ มาสร้างเป็น Physical Tables ใน Data Warehouse
2. **สร้าง Views หรือ Data Marts:** ทำการเขียน SQL Query สร้าง View เฉพาะสำหรับแต่ละแผนกหรือแต่ละ Dashboard เพื่อให้ BI Tool ดึงข้อมูลไปแสดงผลได้อย่างรวดเร็ว

## Phase 4: การสร้าง Dashboard (Data Visualization)
1. **เชื่อมต่อ BI Tool:** นำเครื่องมือ BI (เช่น Power BI, Tableau หรือ Looker Studio) มาต่อเข้ากับ Data Warehouse (Views ที่สร้างไว้)
2. **ออกแบบและพัฒนา Dashboards:**
   - **Executive Dashboard:** แสดงภาพรวม KPI ของคณะ/วิทยาเขต (เช่น ยอดเงินทุนวิจัยรวม, จำนวนผลงานตีพิมพ์รวม)
   - **Research & IP Dashboard:** เจาะลึกจำนวนโครงการวิจัย แหล่งทุน และสิทธิบัตร/อนุสิทธิบัตร แยกตามคณะหรือสาขาวิชา
   - **Academic Performance Dashboard:** ตรวจสอบจำนวนผลงานวิชาการ บริการวิชาการ และการตีพิมพ์ แยกตามบุคคล (Researcher)
3. **กำหนดสิทธิการเข้าถึง (Row-Level Security):** ทำให้คณบดีเห็นข้อมูลทั้งคณะ แต่หัวหน้าภาควิชาเห็นแค่ข้อมูลในภาควิชาตนเอง

## Phase 5: การทำงานอัตโนมัติและการบำรุงรักษา (Automation & Maintenance)
1. **Automate Pipeline:** ใช้เครื่องมือเช่น Apache Airflow, dbt, หรือ Cloud Functions เพื่อตั้งเวลาให้ระบบดูดไฟล์ Excel ใหม่ที่เข้ามาทุกเดือน แล้ววิ่งผ่านกระบวนการ ETL ไปยัง Dashboard อัตโนมัติ
2. **Data Quality Checks:** ตั้งระบบแจ้งเตือน (Alert) หากไฟล์ต้นฉบับที่ส่งมามีรูปแบบคอลัมน์เปลี่ยนไปจากเดิม หรือมีข้อมูลสูญหาย

## Phase 6: การพัฒนา Custom Web Dashboard (`dashboard.html`)
เนื่องจากโปรเจกต์มีการใช้ Web Dashboard เข้ามาเสริมแผนงาน แผนส่วนนี้จึงครอบคลุมการพัฒนาหน้า Dashboard ในรูปแบบเว็บแอปพลิเคชัน:
1. **การออกแบบและพัฒนาส่วนหน้า (Front-end Development):**
   - โครงสร้างและสไตล์: ใช้ HTML5 และ CSS สมัยใหม่ (รวมถึง CSS Variables) เพื่อสร้างดีไซน์ที่ดูพรีเมียม ตอบสนองได้ทุกหน้าจอ (Responsive)
   - การแสดงผลกราฟ: ใช้ไลบรารี Chart.js ร่วมกับ `chartjs-plugin-datalabels` เพื่อแสดง Data Visualization ให้เห็นภาพรวมและตัวเลขชัดเจน
   - โครงสร้าง UI: แบ่งส่วนประกอบหลักเป็นระบบ Tab นำทาง, KPI Cards, กราฟ, และตารางข้อมูล
2. **การเชื่อมต่อและดึงข้อมูล (Data Integration & Binding):**
   - นำผลลัพธ์จากกระบวนการ ETL หรือ Data Warehouse มาแปลงเป็นรูปแบบ JSON (เช่น `metadata.json`, `ku_eng_personnel.json`)
   - ใช้ JavaScript (Fetch API หรือดึงจากไฟล์โดยตรง) เพื่อนำข้อมูลมาผูก (Bind) เข้ากับ Chart.js และ Component ต่างๆ แบบอัตโนมัติ
3. **การเพิ่มความยืดหยุ่นและประสบการณ์ผู้ใช้ (Interactivity & UX):**
   - ระบบตัวกรอง (Filtering): พัฒนาระบบให้ผู้ใช้สามารถกรองข้อมูลตามช่วงเวลา คณะ ภาควิชา หรือประเภทผลงานได้
   - การโต้ตอบ (Interactivity): เพิ่มระบบ Hover states, Tooltips บนกราฟ, และ Animation การแสดงผลข้อมูลที่ลื่นไหล
   - การจัดการข้อมูลจำนวนมาก: ใส่ลูกเล่นเลื่อนหน้าจอ (Scroll) สำหรับตารางหรือนำเสนอในรูปแบบ Pagination

## Phase 7: การยกระดับการวิเคราะห์และปรับปรุง Dashboard (Dashboard Enhancements)
เพื่อตอบสนองต่อความต้องการในการตัดสินใจเชิงบริหารและทำให้ Dashboard ดูเรียบง่ายแต่ทรงพลัง จะต้องมีการปรับปรุงเพิ่มเติมดังนี้:

1. **การปรับปรุง UI/UX ของกราฟและการโต้ตอบ (Chart Optimization & Controls):**
   - **รวบรวมกราฟรายเดือน (Time-series consolidation):** แทนที่จะแสดงกราฟแยก 12 ช่องสำหรับ 12 เดือน ให้ยุบรวมเป็นกราฟเดียวและใช้ปุ่ม/Dropdown สำหรับ Filter เลือกช่วงเวลาที่ต้องการดูแทน เพื่อลดความซับซ้อนและให้หน้าเว็บดูสะอาดตา
   - **ระบบจัดเรียงข้อมูล (Sorting):** เพิ่มปุ่มควบคุมการจัดเรียงบนกราฟและตาราง เช่น "เรียงตามจำนวนผลงาน (มาก-น้อย)" หรือ "เรียงตามงบประมาณ (มาก-น้อย)"
   - **ปรับปรุงกราฟ SDG (Diverging Bar Chart):** ยุบรวมกราฟ SDG ให้เหลือเพียงกราฟเดียวในรูปแบบ Diverging Bar Chart โดยอ้างอิงข้อมูลสรุปทั้งหมดจากบริบทเดิม (Context Summary) เพื่อให้เปรียบเทียบทิศทางได้ง่ายขึ้น

2. **การเพิ่มมิติการวิเคราะห์เชิงลึก (Advanced Analytics & KPIs):**
   - **กราฟเปรียบเทียบปีก่อน (YoY Comparison):** เพิ่มกราฟในหน้า "ภาพรวม" เพื่อเปรียบเทียบผลการดำเนินงานปัจจุบันกับช่วงเวลาเดียวกันของปีก่อนหน้า (ทั้งนี้ต้องมีการนำเข้าข้อมูลย้อนหลังเพิ่มเติม เนื่องจากปัจจุบันมีข้อมูลเพียง 5 เดือน)
   - **การตั้งเป้าหมายและตัวชี้วัด (KPIs for Evaluation):** นำระบบ KPI เข้ามาจับในกราฟ (เช่น ใส่เส้น Target Line) เพื่อใช้ประเมินผล ติดตามภาพรวม และทำให้ Dashboard สามารถใช้ประกอบการตัดสินใจและตรวจสอบประเด็นที่ต้องปรับปรุงได้จริง
   - **การเปรียบเทียบงบประมาณภาควิชา (Budget vs Actual):** นำข้อมูลงบประมาณที่ตั้งไว้ของแต่ละภาควิชา มาแสดงเปรียบเทียบกับผลการดำเนินงานจริง เพื่อประเมินความคุ้มค่าและดูว่าใช้งบประมาณตามเป้าหรือเกินกว่าที่กำหนด

3. **การวิเคราะห์สัดส่วนบุคลากร (Personnel Participation):**
   - **การมีส่วนร่วมของบุคลากร:** นำฐานข้อมูลบุคลากรจาก `ku_eng_personnel.json` (รายชื่อบุคลากรทั้งหมดในแต่ละภาค) มาไขว้กับข้อมูลผลงาน เพื่อแสดงให้เห็นถึง "สัดส่วนการมีส่วนร่วมของบุคลากร" ในการพัฒนาและดำเนินงานของแต่ละภาควิชา (เช่น อาจารย์ที่มีผลงานเทียบกับอาจารย์ทั้งหมดในภาค)
